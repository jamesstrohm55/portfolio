Chess Engine

Overview

This chess engine is a ground-up implementation of the complete rules of chess in modern C++17. It handles every edge case — castling rights, en passant captures, pawn promotion, check/checkmate/stalemate detection — all with an efficient board representation and move generation system.

The engine uses ray-casting for sliding piece attack detection and maintains a complete game state history stack, enabling move/undo operations essential for search tree traversal in AI implementations.

Key Features

Complete Move Validation
Every move is validated against the full chess ruleset including pins, discovered checks, and illegal king moves into attacked squares.
Ray-Cast Attack Detection
Sliding pieces (bishop, rook, queen) use directional ray-casting to efficiently detect attacks along diagonals, ranks, and files.
Special Moves
Full implementation of castling (kingside/queenside with right tracking), en passant capture, and pawn promotion to any piece.
Move/Undo System
Complete game state history with push/pop semantics. Every move can be undone, restoring the exact previous board state including castling rights.
Algebraic Notation
Standard algebraic notation parsing for move input (e.g., "e2e4", "Nf3") with disambiguation for ambiguous piece moves.
Game State Detection
Automatic detection of check, checkmate, and stalemate conditions after every move, with proper game termination handling.

Challenges & Solutions

  • Pin Detection: Pieces pinned to the king can still move along the pin line. Implemented pin-ray tracking to correctly constrain movement along the pinning axis.
  • Castling Validity: Castling requires checking that the king doesn't pass through or land on attacked squares. Required efficient attack map generation for intermediate squares.
  • State Restoration: The undo system must perfectly restore all game state — not just piece positions, but castling rights, en passant target square, and half-move clock. Used a state snapshot stack.
  • Performance: Move generation for all pieces on every turn needs to be fast for search tree exploration. Optimized with early termination and direction-based move generation tables.

What I Learned

  • Deep understanding of OOP design patterns — polymorphic piece hierarchies, strategy pattern for move generation, and command pattern for undo.
  • Efficient data structure design for board representation and move encoding in constrained memory.
  • Building a CMake project with proper header organization, compilation units, and build configuration.
  • The importance of exhaustive edge case testing — chess has more corner cases than most software.
